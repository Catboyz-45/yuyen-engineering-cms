# นโยบายความเป็นส่วนตัวและการดูแลก่อนประกาศใช้

เพิ่มหน้า `/privacy`, `/cookies`, `/terms` พร้อมลิงก์ท้ายเว็บและข้อความแจ้งก่อนฟอร์มล็อกอินแล้ว หน้านโยบายอ่านข้อมูลบริษัทและสถานะการรับรองจากฐานข้อมูล หากฐานข้อมูลขัดข้องยังเปิดอ่านได้ โดยแสดงเป็นฉบับร่างและส่วนท้ายที่มีแค่ชื่อบริษัท ไม่มีการบังคับยินยอมการตลาดเพื่อเข้าสู่ CMS

## ตรวจพบอะไรในโค้ด

- คุกกี้จำเป็น `__Host-yuyen_session` (production) / `yuyen_session` (development) อายุจาก `SESSION_ABSOLUTE_HOURS` และ idle timeout จาก `SESSION_IDLE_MINUTES`
- `sessionStorage` ชื่อ `yuyen-ui-flash` เก็บข้อความแจ้งผล แล้วลบเมื่ออ่านหรือจบเซสชันแท็บ
- ไม่มีสคริปต์ analytics หรือ advertising pixel ใน source ณ วันที่ตรวจ 6 กันยายน 2569 ต้องตรวจการ inject ผ่าน hosting/integration เพิ่มก่อนประกาศจริง
- Google Maps เดิมโหลด iframe เมื่อมี URL ปัจจุบันรอผู้ใช้กดยินยอมก่อนสร้าง iframe และปิดได้ ตัวเลือกไม่เก็บข้ามหน้า ไม่มีฐานข้อมูล consent หรือ cookie เพิ่ม
- กำหนด allowlist ของ URL แผนที่ทั้งตอนบันทึกข้อมูลบริษัทและก่อนแสดงผล ใช้ HTTPS เฉพาะ `www.google.com` / `maps.google.com` กับ `/maps/embed` หรือเส้นทางย่อย CSP อนุญาตเฉพาะปลายทางเหล่านี้
- การปิด iframe ไม่สามารถเรียกคืนข้อมูลหรือคุกกี้ที่ Google ได้รับไปแล้ว ต้องใช้ browser/Google privacy settings ประกอบ

## สิ่งที่เจ้าของบริษัทต้องยืนยัน

เอกสารเริ่มเป็น **ฉบับร่าง** และ `noindex` โดยยังเปิดให้ตรวจทานผ่านลิงก์ได้ ไม่แสดงวันที่มีผลบังคับใช้ที่ยังไม่ได้รับรอง

1. ตรวจชื่อบริษัท ช่องทางใช้สิทธิ์ และผู้รับผิดชอบคำร้อง
2. Super Admin กรอก "อีเมลรับคำร้องเรื่องข้อมูลส่วนบุคคล" ในเมนู **นโยบายเว็บไซต์** เป็นอีเมลที่รับเรื่องจริง ไม่ใช้ `contact@example.co.th` หรือข้อมูลจาก seed
3. ยืนยันฐานกฎหมายแต่ละกิจกรรมและข้อมูลที่รับผ่านโทรศัพท์ อีเมล LINE/Facebook
4. ยืนยันผู้ให้บริการจริง (รวม hosting, ฐานข้อมูล, storage, logs, backups) พื้นที่ประมวลผลต่างประเทศ และเงื่อนไขการโอน/การคุ้มครองข้อมูล แล้วกรอกในช่อง "ผู้ให้บริการและพื้นที่จัดเก็บข้อมูล" อย่าอ้างว่ามีมาตรการหรือสัญญาที่บริษัทยังไม่ได้จัดทำ
5. กำหนดระยะเวลา **สูงสุด** ของ AuditLog, บันทึกโฮสติ้ง, คำร้อง/ข้อมูลติดต่อ และสำเนาสำรอง แล้วกรอกในช่อง "ระยะเวลาเก็บข้อมูลที่บริษัทกำหนด" ก่อนรับรอง โค้ดยังไม่มี audit-log purge อัตโนมัติ ข้อกำหนดเก็บอย่างน้อย 180 วันไม่ได้แปลว่าลบอัตโนมัติวันที่ 180
6. ตรวจการรัน `auth:cleanup`, `cms:purge-expired`, `media:cleanup` และขั้นตอนจัดการคำขอลบ รวมถึงสำเนาสำรอง ไม่เปลี่ยนงานลบอัตโนมัติในงานเพิ่มนโยบายนี้
7. หากที่ปรึกษากฎหมายขอแก้ถ้อยคำส่วนอื่น ให้นักพัฒนาแก้ใน `src/app/(legal)/*/page.tsx` และเปลี่ยน `legalRevision` ใน `src/lib/legal.ts` เป็นวันที่แก้ การเปลี่ยนค่านี้ทำให้หน้านโยบายกลับเป็นฉบับร่างเองจนกว่าจะรับรองใหม่
8. เมื่อตรวจเสร็จ Super Admin ติ๊ก "รับรองและประกาศใช้นโยบาย" ในเมนู **นโยบายเว็บไซต์** แล้วบันทึก (ไม่ต้อง redeploy) ระบบจะถอดป้ายฉบับร่าง แสดงวันที่ประกาศใช้ เปิด indexing และเพิ่ม 3 หน้าใน sitemap ต้องกรอกข้อมูลครบทั้ง 3 ช่องจึงรับรองได้ (ฐานข้อมูลบังคับซ้ำด้วย CHECK constraint) แต่โค้ดไม่สามารถยืนยันว่าอีเมลนั้นมีคนรับเรื่องจริง การรับรองและยกเลิกถูกบันทึกใน audit log เป็น `LEGAL_NOTICE_APPROVED` / `LEGAL_NOTICE_WITHDRAWN`

การเปิดสวิตช์รับรองเป็นขั้นตอนเผยแพร่เอกสาร ไม่ใช่การรับรองว่าองค์กรปฏิบัติตาม PDPA ครบทุกเรื่อง ควรให้ผู้รับผิดชอบข้อมูล/ที่ปรึกษากฎหมายตรวจเนื้อหาตามการใช้งานจริง

## วิธีตรวจการเลือกใช้แผนที่

เปิด Contact ในหน้าต่าง private ที่ไม่มี extension ตรวจ Network ว่าไม่มีคำขอไป Google ก่อนกดเปิด จากนั้นกดเปิดและปิดด้วยเมาส์และคีย์บอร์ด เมื่อเปิดหน้าใหม่ต้องไม่โหลดแผนที่เอง ทดสอบ URL ที่ไม่อยู่ใน allowlist ว่าปิดการแสดงผล ไม่ฝังเว็บอื่น

ชุดทดสอบ `npm run test:unit` ตรวจ allowlist, การไม่สร้าง iframe ก่อนเลือก และการตั้งค่านโยบาย ส่วนการทดสอบเบราว์เซอร์ใช้ฐานข้อมูลทดสอบว่างที่ migrate แล้วตาม `.env.test.example` (ห้ามใช้ฐานข้อมูลจริง):

```sh
NEXT_PUBLIC_COMPANY_MAPS_EMBED_URL='https://www.google.com/maps/embed?pb=privacy-test' PLAYWRIGHT_PORT=3109 npm run test:e2e:privacy
```

ปิด dev server เดิมบนพอร์ตทดสอบก่อนรันเพื่อให้รับค่าใหม่ ตัวทดสอบจำลองคำตอบ Google ไม่ติดต่อ Google จริง และไม่เขียนข้อมูลลงฐานข้อมูล ตรวจทั้งมือถือ/เดสก์ท็อป ลิงก์นโยบาย หน้าเข้าสู่ระบบ การใช้คีย์บอร์ด และการเปิด/ปิดแผนที่ หากไม่กำหนด URL ตัวอย่างจะข้ามเฉพาะกรณีแผนที่ ต้องไม่ข้ามกรณีนี้ในการตรวจรับ ต้องไม่มีข้อมูลบริษัทในฐานทดสอบ (ห้ามรัน seed) เพื่อให้ใช้ URL สำรองจาก environment เพราะเมื่อบันทึกข้อมูลบริษัทใน CMS แล้ว ค่าใน CMS มีผลเหนือ environment เสมอ หากฐานมีข้อมูลบริษัท ตัวทดสอบจะหยุดพร้อมข้อความแจ้ง

หากเพิ่ม analytics/โฆษณา ต้องทำ consent manager ก่อนโหลดสคริปต์ รองรับการปฏิเสธ/ถอน บันทึกหลักฐานและ version ตามความจำเป็น และปรับเอกสารให้ตรง ห้ามเพิ่มปุ่มยอมรับที่ไม่ควบคุมการโหลดจริง
